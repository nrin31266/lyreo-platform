# Admin Web UI

Prioritize desktop and large screens: polished layouts, efficient use of space, and fast authoring workflows. Reuse existing shadcn components, semantic tokens, and translations. Keep basic responsive behavior and accessibility; spend time and tokens on detailed mobile/tablet design or browser checks only when requested or directly affected by the change.

Prefer a viewport-sized workspace when content fits, but allow the page to grow and scroll naturally for long content or short desktop screens. Keep the player and primary actions accessible with collapsible panes and sticky positioning. Use independent scroll regions only for bounded lists/history, avoid nested scrolling, and leave room for focus rings and sticky controls.
