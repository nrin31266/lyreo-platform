# Admin Web UI

Prioritize desktop and large screens: polished layouts, efficient use of space, and fast authoring workflows. Reuse existing shadcn components, semantic tokens, and translations. Keep basic responsive behavior and accessibility; spend time and tokens on detailed mobile/tablet design or browser checks only when requested or directly affected by the change.

Prefer task pages that fit within 100dvh (100vh fallback), including the shell header. Keep headings, tabs, and primary actions visible; give long tables, lists, and forms their own scroll regions using min-height: 0. Choose columns and pane sizes for desktop workflows instead of growing the entire page.
